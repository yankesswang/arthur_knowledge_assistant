# /mimi-digest

把一篇 MimiVsJames（或任何來源）個股投資筆記，跑成總表可無痛接上的標準化條目。核心原則：**筆記的「📊 個股操作摘要」區塊是唯一資料來源，總表只彙整、不重寫。**

## 輸入
- 一個筆記檔路徑（`投資/…md` 或 `Clippings/…md`），或貼上的 Markdown / Substack URL。
- 目標總表：`/Users/yankesswang/Documents/arthurwang_DB/投資/mimi操作建議總表.md`（非 MimiVsJames 來源改用 `投資操作建議總表.md`）。

## 流程

### 1. 判斷來源與類型
- 讀 frontmatter `source:`/`url:` 是否含 `mimivsjames`。非 mimi → 分流到 `投資操作建議總表.md`。
- 個股筆記才做（有明確標的+進出場）；純宏觀/心法 → 只做「盤勢摘要」或跳過。

### 2. 在筆記頂端（frontmatter 下、TL;DR 上）插入「📊 個股操作摘要」區塊
格式固定，欄位對齊總表。**價位缺漏一律標「作者未給」，絕不臆造。**

```markdown
## 📊 個股操作摘要（總表同步用）

> 本區塊是 [[mimi操作建議總表]] 的**唯一資料來源**，欄位對齊總表。改這裡就等於改總表。
> 動作定義：🟢 佈局/加碼/持有 ｜ 🟡 轉保守/等企穩 ｜ 🟠 減碼/逢高調節 ｜ 🔴 出場/避開 ｜ ⚪ 觀察。當時價＝yfinance 當日收盤。

- **板塊**：<板塊名>
- **首推日期**：YYYY-MM-DD ｜ 來源：MimiVsJames Substack
- **一句話結論**：<主軸>

| 標的 | 定位 | 進場策略 | 當時價 | 目標/停損 | 催化劑（時間） | 動作 |
|------|------|---------|-------|----------|--------------|------|
| **TICKER** | … | … | $X | … | … | 🟢 佈局 |

> [!warning] 核心風險
> …
```

### 3. 抓價（yfinance）
用 `scripts/fetch_prices.py`（見同目錄）。給 `TICKER,YYYY-MM-DD` 清單，回當日收盤（首推當時價）＋最近收盤（現價）＋報酬率。
- 台股加 `.TW`（如 `2454.TW`，值為 TWD）、深滬 `.SZ/.SS`（值為 CNY），標注幣別。
- 未上市/未 IPO → 標「未掛牌」+ 用 IPO 定價。
- **低價股（<$10）值常與現實 ticker 對映不符**，一律加 ⚠️ 提示使用者複核。

### 4. 同步進總表（三種情況）
- **新標的** → 在對應板塊章節新開一個 block（新格式，見下）。
- **既有標的（新觀點）** → 在該標的「觀點演變（不同時期論點 × 差異對比）」表**加一列**，更新頂部「當前動作」為最新，並在「比前次變了什麼」欄寫出差異（升級/降級/翻多/翻空/新增角度）。
- **重複 block** → 合併成一個：頂部「當前動作」（最新結論）＋「觀點演變對比表」（各期收斂，不刪推理）＋「基本面(參考)」一行。

### 5. 維護總表頭
- frontmatter `stocks:` 補新 ticker（唯一 ticker 真相，索引自動化用）。
- 「零、當前狀態儀表板」：把該標的按燈號歸入 🟢持有/佈局 · 🟠減碼/🔴出場 · 🔴輸家警示，附報酬率。
- 跨章重複只留一個 canonical，其他改成「→ 見 X 章」cross-ref 指標。

### 6. 加進待閱讀清單（必做，別漏）
處理完的來源筆記要進 `待閱讀清單.md`。一律走共用寫入器，**不要直接改清單檔**（它管週區塊輪替、去重、作者分組、dataless 降級）：

```bash
python3 /Users/yankesswang/Projects/Arthur_App/scripts/lib/article_list.py \
  --link "<筆記檔名，不含 .md>" --section "投資"
```
- 作者分組自動依 frontmatter 判斷（mimivsjames → `mimi`）；非 mimi 來源也照跑，會落到對應作者小區。
- 已在清單會回「已存在，不重複加入」——每小時 digest 產的筆記本來就加過了，重跑無害。
- 印出 `⚠️ 寫不進去（已排進 pending queue）` 也算成功，下次任一管線寫入時會補；回報時照實轉述輸出。
- 一次處理多篇就每篇各跑一次。

## 總表個股 block 標準格式

```markdown
#### TICKER（Name）— <一句話定位>

**🟢 當前動作（YYYY-MM-DD，當時 $X → 現 $Y，±Z%）：<動作>——<一句>**

| 進場 | 目標 | 停損 | 關鍵催化劑 |
|------|------|------|-----------|
| … | … | … | … |

**觀點演變（不同時期論點 × 差異對比）**   ← 僅多時期才有
| 日期 | 當時價 | 動作 | 該篇核心論點 | 比前次變了什麼 |
|------|-------|------|------------|--------------|
| … | $X | 🟢 | … | — 起點 |

**邏輯**：…
**基本面(參考)**：<EPS/毛利率/營收等數據壓成一行>
**風險**：…
📖 [[來源筆記1]]｜[[來源筆記2]]
```

## 硬規則
- 操作在上、基本面降級為一行；不要把財報數字混進操作欄。
- 每檔一個 canonical block（DRY），舊觀點收進時間軸、不並排。
- 相對日期一律轉絕對（「現在」→ YYYY-MM-DD）。
- Edit 大 block 若比對失敗，改「只換 header+表格」小範圍替換（callout 文字常有隱形字元差異）。
- 報酬率 = (現價 − 當時價) / 當時價；標的曾建議「減碼/出場」而事後下跌 = 驗證成功，要在條目點出。

## ⚠️ 轉格式踩過的坑（務必遵守，否則 stock-radar parser 會抓錯）
- **轉新格式時「只換 header+表格」會留下舊 callout** → 同一 block 同時有 `**邏輯**` 和殘留的 `> [!tip]/[!warning]/[!danger]`，造成重複＋mislabel。**改完務必連同舊 callout 與重複的 `📖 參考來源` 一起刪掉**，只留新格式的 `**邏輯**`/`**風險**`/單一 `📖`。
- **callout 依「標題文字」歸類，不要依類型**。原文常亂用（例：MSFT 把「操作邏輯」放進 `[!warning]`）。規則：標題含「風險」→ 風險；含「邏輯/操作/理由」→ 邏輯。純看 `[!warning]=風險` 會把邏輯塞進風險欄。
- **`#### TICKER（Name）— desc` 的破折號兩側不保證有空格**（`）—desc` 常見）。parser 用 `re.split(r'\s*[—–―─]\s*', line, 1)` 切 ticker/desc；若 desc 內含 `/`（如「避開/不抄底」）而破折號沒被正確切開，ticker 會被 `/` 拆成 `TICKER`＋`碎片）` → DB 出現假 ticker。改 header 時別破壞破折號。
- **寫清理/批次腳本要在 `##` 章節邊界斷開 block**（不能只用 `#### ` 切），否則每章最後一個 block 會吃掉下一章標頭、`📖` 跑位。
- **抓 wikilink 來源要「先收集再刪 callout」**：`> 📖 參考來源` 若是 callout 的接續行（`>` 開頭），會被 callout body 吞掉導致來源遺失。先掃全 block 的 `📖` 收集 `[[...]]`，再處理 callout。
- 動到總表後跑 `uv run python scripts/export_mimi_json.py` 檢查：`sources`/`direction` 的 empty 數應接近 0，`new/old format` 比例合理，無 KeyError/假 ticker。

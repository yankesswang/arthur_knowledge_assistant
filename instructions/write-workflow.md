# 內容創作工作流

這份文件是 Arthur 的 **個人知識管理 → 內容輸出** 的完整循環系統。
分兩個部分：
- **Part A（一 到 七）**：日常運作流程（捕捉 → 選題 → 生產 → 驗證 → 復盤），適用所有主題
- **Part B（八 到 十三）**：AI/LLM 技術內容的專屬 Prompt 工具包

---

## Part A：日常運作流程

---

## 一、系統底層（一次性建立，持續迭代）

這些是內容系統的基礎設施，不建好後面每篇都要重新發明輪子。

### 1-1 語料庫：讓 AI 學會你的聲音

把你說過的話全部存下來——推文、觀點碎片、聊天記錄、隨手筆記。提煉成一份**寫作風格指南**，AI 每次寫稿前先讀它。

風格指南必須包含：
- 5 條你總是遵守的規則（例：「先下結論再給理由」、「喜歡用數字不用形容詞」）
- 5 條你從不使用的模式（例：「不用雞湯收束」、「不替讀者說話」）
- 2–3 篇聽起來最像你的參考貼文

### 1-2 去 AI 味清單（Avoid-Slop 文件）

每次發現一個 AI 味模式就加進去，持續更新。初始清單：

| 刪掉 | 類型 |
|------|------|
| 賦能、閉環、打通、底層邏輯 | 行銷大詞 |
| 「你可能覺得……」「很多人會問……」 | 替讀者說話 |
| 「記住」「一定要」「核心就一句話」 | 指令語氣 |
| 「90% 的人不知道」 | 虛構數據 |
| 一句話。一個詞。成段。 | 戲劇感碎句 |
| **加粗金句口號** | 直接刪 |
| groundbreaking、game-changing | 重要性通膨 |
| em dash 過度使用 | 目標是零 |
| actually、literally、quietly | 填充副詞 |

### 1-3 素材庫

不是剪貼簿，要有結構：
- 競品帳號拆解（記錄：定位、爆款結構、書籤率 / 曝光數據）
- 可復用框架 / 金句 / 拆解過的選題角度
- 自己發布過的勝出帖子（附數字）

使用方式：每次寫新文章先翻素材庫，看同類話題誰寫過、什麼角度跑出數據、什麼結構讀者願意存。

### 1-4 方法論庫

從自己的數據長出來的規則，不是想出來的。每週復盤後把「有效的做法」沉澱進來。

## 二、輸入 — 知識怎麼進場

### Vibe Reading 流程（文章、書、課程、論文都適用）

```
Step 0：零基礎時 → 讓 AI 畫「最粗的認知地圖」（3–5 條，不是 30 條）
         Prompt：「假設我完全不懂 X，請用最笨的比喻給我一張最粗的認知地圖：
                  它解決什麼問題？核心概念大概有幾個？它們之間什麼關係？」

Step 1：翻之前先寫「我要從這裡拿什麼」（3–5 條具體需求）
         → 這幾條已能篩掉 60% 的內容

Step 2：把目錄丟 AI，只標三類（不要讓 AI 總結章節，只標位置）：
         ✅ 書裡有 & 我需要 → 候選精讀
         ❌ 書裡有 & 不需要 → 跳過
         ⚠️ 我需要 & 書裡沒有 → 去別處找

Step 3：你自己判斷優先級（AI 不懂你手頭在解決什麼）
         現在要掌握 → 精讀（Step 4 模式 A）
         只要印象   → AI 轉述（Step 4 模式 B）
         暫時不需要 → 扔進 backlog

Step 4：獲取內容
         模式 A：自己讀（核心知識、需要深度理解）
         模式 B：AI 轉述（輔助知識、只要知道「存在過」）

Step 5（最重要的質量閘門）：
         1. 用自己的話寫總結 → 扔給 AI 挑錯（不是擴展，是校正）
         2. 問自己：這個知識點現在能拿來干什麼？

Step 6（選填）：費曼法
         假設要教給完全不懂的人：從哪裡起手？用什麼例子？
         做不下來 = Step 5 的壓縮沒有真的發生
```

**AI 挑錯者系統提示（直接複製使用）**：

```
你是我的讀書挑錯者，不是助理。
我會把我的一句話理解發給你。你的工作是：
1. 對照原文，找出我理解裡漏掉的關鍵維度
2. 找出我理解裡有沒有錯的、歪的、想當然的部分
3. 如果我的理解基本正確，直接說「對」，不用補充
4. 不要擴展、不要舉更多例子、不要鼓勵我
默認人格是尖銳但簡短。我自己會補細節。
```

### 跨領域學習：每個新概念都問四問

1. 它本質解決什麼問題？
2. 為什麼用這個解法？換個時代或市場還成立嗎？
3. 反例是什麼？（讓 AI 攻擊你的理解）
4. 和我已知的哪個概念連得上？底層相似還是本質不同？

## 三、選題 — 策略化，不隨機

### 選題池管理

永遠維持：
- 10+ 個隨時能寫的選題（資料齊、角度清楚）
- 10+ 個需要補素材的備選

狀態流：`選題池 → 待深化 → 創作中 → 已發布`

### 目標決定選題類型

| 當前目標 | 對應選題類型 | 原因 |
|---------|------------|------|
| 要曝光 | 剛需工具教程、AI + 搞錢、資源合集 | 讀者存起來用，書籤率高 |
| 要漲粉 | 人設解析文、真實經歷復盤 | 看了想 follow 這個人 |
| 要沉澱 | 方法論復盤、系統拆解 | 建立長期資產，搜尋流量 |

### 四條選題賽道

| 賽道 | 優勢 | 注意 |
|------|------|------|
| 項目實戰 | 真實感強，信任度高 | 需要有真實案例才能寫 |
| AI 搞錢拆解 | 曝光高 | 要找到有數據支撐的好案例 |
| 低門檻草根生意 | 話題廣泛 | — |
| AI 新範式趨勢 | 時效性強 | 衰退快，要快寫快發 |

### 爆款結構

```
我做了 X（真實經歷）
+ 結果是 Y（具體數字）
+ 你可以這樣複製（可執行路徑）
```

沒有爆款是抽象概念。「幫你省時間」是底層傳播邏輯：我幫你試過了、踩坑了、整理好了，你照著來。

## 四、每日捕捉（20 分鐘）

每天遇到值得記錄的東西，分到四類，每條三個標籤以內：

| 類別 | 定義 | 記錄格式 |
|------|------|---------|
| **Observations（觀察）** | 在 Agent / LLM 領域注意到的現象，不分析 | `[工具/現象] — [我注意到什麼] — [和預期的差距]` |
| **Reactions（反應）** | 對讀到/看到/用過的東西的真實感受，不是摘要，是意見 | `[來源] — [我的真實反應] — [為什麼讓我停下來]` |
| **Patterns（模式）** | 跨 paper、跨 framework、跨案例重複出現的規律 | `[規律描述] — [出現在哪些案例] — [為什麼重要]` |
| **Numbers（數字）** | 真實的 benchmark、成本、latency、token 數字 | `[指標] [數值] [來源] [比較基準]` |

**四個來源的輸入方式：**

1. **論文/技術報告**（一篇，只看最重要的部分）：不要全讀。找到讓你說「等等，這個假設是認真的嗎？」的那一段。格式：`[論文名] — [讓我停下來的那句話] — [我的真實反應]`

2. **AI 產品或工具的真實行為**（你親手試的）：格式：`[工具/model] + [我做了什麼] + [它的實際行為] + [和我預期的差距]`

3. **社群中的真實問題**（不是 hype，是抱怨或疑惑）：Twitter、Discord、Reddit 上 practitioners 在卡什麼。格式：`[來源] — [問題本身] — [我認為根本原因是什麼]`

4. **一個自己的判斷**（今天你認為什麼是對的）：格式：`我認為 [X]，因為 [Y]，如果 [Z] 我就會改變這個看法`

## 五、每日捕捉 Prompt

```text
我將貼入今天在 Agent/LLM 領域的 5-10 條原始觀察或筆記。

對每一條，做三件事：
1. 把觀察壓縮成一句有力的句子（保留我的語氣，不要變得學術腔）
2. 判斷它是哪個類別：觀察 / 反應 / 模式 / 數字
3. 建議 Vault 中哪一條現有筆記應該和它連結（如果有）

評估標準：這條筆記是否讓一個做 AI 產品的人看了會說「對，我也有這個感覺，但我說不清楚」

原始輸入：[貼入]
```

## 六、每週連結 Session

每週一次，把本週新增的筆記和舊 Vault 連起來。**跨領域的連結才值錢。**

```text
以下是我本週在 Agent/LLM Vault 中新增的筆記：
[貼入本週所有筆記]

找出所有非顯而易見的連結。不要表面的連結（「都是 LLM 的」= 不算）。

我要找的是：
- 同一個工程問題在不同 framework 中被用不同方式解決
- 一個 Agent 架構的設計決策，和另一個完全不同領域（管理學、生物學、系統設計）的邏輯是一樣的
- 一個社群 practitioner 抱怨，和某篇論文的 limitation section 在說同一件事
- 兩個看起來對立的觀點，其實在不同條件下各自是對的

對每個找到的連結：給我一句話橋接這兩個想法。
那句話必須讓人看了說「我沒想到但現在覺得明顯」——那就是一個好的內容 hook。
```

## 七、生產 — 從想法到草稿

### 7-1 填 Writer Context Packet（每篇必填）

**填不出來 = 還沒想清楚，不要開始寫。**

```
thesis:       這篇要證明的一句話
reader:       應該收藏它的那個具體的人（不是「所有人」）
proof:        我被允許用的數字 / 截圖 / 故事（沒有就不要發）
angle:        意外的框架（讀者沒想到你會從這個角度切）
constraints:  格式、長度、語氣、這篇不能用的詞
voice:        2–3 行聽起來像我的句子（從語料庫取）
risks:        什麼地方最可能讀起來像 AI 寫的
open_loops:   我還沒搞清楚的地方，讓 AI 寫稿時標記出來
```

Packet 填完才能開始起草。和草稿放在同一個資料夾（`brief.md`）。

### 7-2 路由判斷：這篇是哪種類型？

| 類型 | 說明 | 素材來源 |
|------|------|---------|
| 原創 | 從你的筆記、對話記錄、觀察直接提取 | 你自己的 Vault / AI 對話歷史 |
| 再利用 | 擴展已發布的內容（延伸篇、系列衍生）| 已發布存檔 |
| 改寫 | 取外部素材，通過你的視角翻譯 | X 書籤、文章、訪談 |
| 研究 + 構思 | 輸出不是文章，是磨礪後的角度清單 | 多來源 |

### 7-3 起草原則

- AI 寫稿前先讀語料庫的風格指南
- 只傳入 Packet，不要把整個知識庫倒進 context（緊湊的 Packet > 巨大的 context 窗口）
- 緊湊的 context 幾乎每次都打敗巨大的 context 窗口，原因：模型寫出無聊安全的內容，是因為 context 裡沒有任何東西是關鍵的

### 7-4 長文銜接（Substack / Medium）

Packet 填完後，切換到 `write-substack.md` **四、生成 Prompt 模板**，依文章類型選擇：
- **類型 A（英文技術長文）**：`thesis` → 核心論點、`proof` → 關鍵數字、`angle` → 開場模式
- **類型 C（中文敘事長文）**：`thesis` → 核心轉折點、`reader` → 目標讀者、`voice` → 說書人語氣錨點

## 八、驗證 — 發布前的三道閘

**不可談判的原則：每篇草稿都要人工收尾。系統是加速器，不是自動駕駛。把它當自動化，它就衰退。**

### 閘 1：去 AI 味（過 Avoid-Slop 清單）

每篇發布前必過一遍（見一、1-2）。發現新模式就加進清單。

### 閘 2：Bookmarkability 評分（8/12 分才發）

每項 0 / 1 / 2 分，滿分 12：

| 項目 | 問自己 |
|------|--------|
| 節省未來任務 | 讀者存起來，未來某天會用到嗎？ |
| 有具體證明 | 有數字、截圖、具名案例嗎？ |
| 有可復用收穫 | 有模板 / 框架 / 清單 / 步驟嗎？ |
| 有具體受眾 | 這是「為誰寫的」，讀了就知道嗎？ |
| 不需作者在場 | 沒有我的解釋，讀者自己能用嗎？ |
| 有視覺呈現 | 有截圖 / 圖表嗎？ |

低於 8 分：送回重寫，不是丟棄。大多數壞草稿只是缺了某一行，修那一行，重新評分，發布。

### 閘 3：標題四問

- 有具體數字嗎？
- 有身份標籤嗎？（「一人創作者」「做了 X 年的人」）
- 有反差嗎？（「最有生產力的人反而最有落後感」）
- 讀者看完標題知道能得到什麼嗎？

## 九、復盤 — 讓系統複利

### 復盤節奏

- 發布後 24h 記錄一次
- 發布後 72h 記錄一次
- 每週彙總一次

### 追蹤指標

| 指標 | 說明 |
|------|------|
| 書籤率 | 最重要。哪篇有長期價值，不只有即時曝光 |
| 曝光 | 觸及廣度 |
| 漲粉數 | 人設文漲粉 >> 教程文（教程文讀者存了就走）|
| 回覆 / DM | 話題共鳴程度，下一篇的選題來源 |

### 復盤後的動作

- **勝出帖子** → 複製進素材庫，附數字，下次 Packet 直接引用
- **失敗帖子** → 更新 Avoid-Slop 清單 / 修禁用模式 / 調整想法過濾器
- **有效規律** → 沉澱進方法論庫（從數據長出來，不是想出來的）
- **留言 / DM 裡的問題** → 直接捕捉進選題池

護城河在這裡：下一篇的 Packet 因為這週的數據而更清晰。大多數人在發布後就停了，系統從這裡才開始複利。

## 十、Content Brief（先寫 Brief，再寫內容）

**Brief 是你和自己的合約，不是大綱。一句話說不清楚 = 還沒準備好。**

```text
One thing（核心洞見）：
[這篇內容圍繞的單一觀點。一句話說不清楚 = 還沒準備好]

Proof（佐證）：
[一個具體的：真實測試結果 / benchmark 數字 / 你自己踩過的坑 / 實際的 code 行為]
不接受：「很多人都說」「研究顯示」這種模糊描述

Reader transformation（讀者轉變）：
[讀完之後，一個做 AI 產品的工程師知道或能做什麼是之前不行的？]

Hook（開頭）：
[第一句或前兩句，讓做 Agent 的人停下來的那個說法]

Closer（結尾）：
[最後一句，讓人想轉發或存起來的那個句子]
```

**Brief 生成 Prompt：**

```text
我想寫一篇關於 [主題] 的 [LinkedIn 貼文 / 推文串 / 技術文章]。

這是我的受眾：做 AI 產品、研究 LLM、建 Agent 系統的人。
他們討厭：buzzword、沒有具體細節的觀點、重複主流說法。
他們喜歡：真實踩坑的細節、違反直覺的觀察、可以直接用的 pattern。

以下是我提取的原始筆記：
[貼入連結的筆記]

幫我完成這份 Brief：
One thing:
Proof:
Reader transformation:
三個可能的 Hook（按衝擊力排序）:
三個可能的 Closer（按讓人想轉發的程度排序）:

現在不要寫內容，只寫 Brief。
```

## 十一、文章生成 Prompt

Brief 確認之後才用這個。

```text
你用我的聲音寫作。

我的讀者：做 LLM 應用、研究 Agent 架構、在業界建 AI 系統的人。
他們的背景：知道 transformer 怎麼運作，但不一定讀每篇論文。
他們的痛點：分不清哪些研究真的能用、哪些只是 benchmark 好看。

我的寫作風格：
- 短句。每段最多三行。
- 從我自己的測試、踩坑、或具體觀察出發，不從定義出發。
- 如果說一個觀點，必須有一個具體例子或數字撐住。
- 不用「值得注意的是」「不可否認地」這種填充詞。
- 可以有立場，可以說「我認為 X 是錯的，因為」。
- 技術術語保留英文原文（context window、tool call、ReAct、RAG）。

以下是已確認的 Content Brief：
[貼入 Brief]

以下是來源筆記：
[貼入連結筆記]

寫完整內容。
- 用我真實測試或真實觀察開頭，不用定義或背景介紹開頭。
- 每個論點必須有具體的技術細節，不能只有結論。
- 如果有 code 邏輯、prompt 結構、或架構對比，用 code block 呈現。
- 結尾讓人有一個明確的「所以我現在應該去試什麼」。
```

## 十二、常用內容角度

這些是 Agent/LLM 領域最容易引發共鳴的切入點：

- **「我以為 X，結果發現 Y」**：記錄預期和實際行為的落差
- **「所有人都說 X，但沒人告訴你 Y」**：拆解流行說法背後被忽略的前提
- **「用 [具體工具/方法] 做了 [具體事]，cost 從 X 降到 Y」**：真實數字 + 可複製步驟
- **「[paper 名] 最重要的不是結論，是它的 [具體細節]」**：幫讀者跳過全文
- **「這個 Agent 架構在 [具體條件] 下會壞掉，因為」**：反例比正例有記憶點
- **「[舊方法] vs [新方法]，我都試了，這是真實差距」**：對比 + 親測

## 十三、複利機制（AI/LLM 主題）

```
今天的觀察 → Vault → 連結 → Brief → 內容 → 數據 → 回到 Vault
```

- 每篇發布的內容 → 帶表現數據（按讚、轉發、留言問題）存回 Vault
- 表現好的內容 → 記下「什麼角度 + 什麼具體細節」讓它起效
- 留言裡的問題 → 下一篇的選題，直接捕捉進 Observations

# AI 技術筆記格式規範（課程 / 講座）

每次整理 AI 技術筆記（課程錄影、技術演講、混合型論文講座），必須遵循以下格式。
核心原則：**保留論述結構，不壓縮推理過程；圖表與原文並存，讓讀者能重建思路。**

> **語言、圖片判斷、速查表格式**見 CLAUDE.md 全域規範，本文不重複。
> 如果整理的是純學術論文（無背景說明），請改用 `note-paper.md`。

---

## 筆記類型判斷

先判斷類型，對應使用不同主體結構：

| 類型 | 適用場景 | 結構特點 |
|------|---------|---------|
| **A. 課程 / 講座** | 課程錄影、技術演講、教學系列 | 跟隨講者邏輯，主題導向，無固定章節 |
| **B. 論文閱讀筆記** | arXiv 論文、會議論文（含大量背景說明） | 動機 → 方法 → 實驗 → 結論 |
| **C. 混合型** | 有論文主體但加入大量背景解說 | 先課程背景，再論文拆解 |

## 1. Frontmatter（必填）

```yaml
---
title: 中文標題
date: YYYY-MM-DD（發布或整理日期）
source: 課程名稱 / 媒體 / 會議（如 NTU CSIE ML、arXiv）
topic: 技術主題（如 LLM 評估 / Agentic Framework / KV Cache 壓縮）
tags:
  - 核心技術1
  - 核心技術2
url: 原始連結（影片、論文、投影片）
---
```

---

## 2. 摘要（必寫，放在標題後）

一段話（3–5 句），說明：
- 這份筆記在講什麼
- 核心問題是什麼
- 最重要的結論或洞見是什麼

**不用 callout 框，直接段落文字即可。**

---

## 3A. 課程筆記主體結構

### 跟隨講者邏輯，不強加章節框架

- `#` H1：講者的**主要討論主題**（大概念或問題）
- `##` H2：**子主題或子問題**
- `###` H3：**具體方法、案例、工具**

### 每個概念的標準寫法

```
- **概念名稱**：一句話定義
    - **子觀點 A**：說明內容
        - **具體例子**：...
    - **子觀點 B**：說明內容
        - **問題/限制**：...
        - **解決方案**：...
```

### 關鍵原則

1. **不只寫結論**：推理過程、類比說明、例外情況都要保留
2. **問題 → 解決方案**：每個概念優先回答「為什麼需要這個」
3. **對比必須完整**：舊方法 vs. 新方法不得壓縮成一句話
4. **圖在哪、筆記在哪**：截圖放在對應概念段落下方，不集中放在文末

## 3B. 論文筆記主體結構（類型 B / C 使用）

### 固定章節順序

```
# 動機與貢獻
# Method Overview（含總覽表格 + 流程說明）
## 各子模組（Tool Cards / Planner / Executor / ...）
# Experiment
## 實驗設定
### Benchmark / 模型比較 / 驗證方式
## 結果
### 主結果 + 與其他方法比較
# Conclusion
```

### 方法說明必須包含

| 元素 | 說明 |
|------|------|
| 總覽表格 | 各子模組一行，功能摘要 |
| 端到端流程 | 用 code block 寫出資料流 |
| 每個模組的 I/O | 輸入是什麼、輸出是什麼、核心操作是什麼 |
| 與舊方法的差異 | 明確說「過去方法的問題在哪」 |

**資料流 code block 格式：**

```
輸入 Query → Planner（高階計畫）
→ Executor（低階指令 + 執行）
→ Context 更新（軌跡儲存）
→ Verifier（是否完成？）
→ 若未完成：回到 Planner 下一步
→ 若完成：Summarizer → 最終答案
```

### 實驗結果必須包含

- Baseline 設定（零樣本 / CoT / 其他框架）
- 主要指標（準確率、速度、壓縮比等）
- **表格**：數字對比，每個表格下方加一行重點說明

## 4. 格式工具規範

### 表格適用情境

| 情境 | 範例 |
|------|------|
| 子模組對比 | 各模組功能、I/O、限制 |
| 方法比較 | 舊方法 vs. 新方法 vs. 本文方法 |
| 實驗設定 | Baseline 設定、超參數 |

不適合用表格：連續推理過程（用 code block）、單一維度的列表（直接 bullet）。

### Code Block 適用情境

| 情境 | 說明 |
|------|------|
| 資料流 / 演算法流程 | 端到端的步驟，每步一行 |
| JSON / 程式碼範例 | 論文中的具體實作 |
| 數字計算過程 | 壓縮比、效能計算 |
| 時間軸 / 因果鏈 | 事件順序或依存關係 |

### 標記規範

| 標記 | 用途 |
|------|------|
| `**粗體**` | 關鍵術語、概念名稱、重要判斷 |
| `*斜體*` | 圖片說明行、補充說明 |
| `` `code` `` | 函式名稱、工具名稱、技術縮寫 |

## 5. 課程筆記特殊結構

### 「問題 → 解決方案」（必用於討論難題的段落）

```
- **問題**：...
    - **原因**：...
    - **解決方案**：...
        - **方法 A**：...
        - **方法 B**：...
```

### 比較型內容（必用表格或對比列表）

```
- **舊方法**：直接讓同一個 LLM 同時規劃與產生命令
    - **問題**：容易導致錯誤，規劃與執行混雜
- **本文方法**：分離 Planner 與 Executor
    - **優點**：低階指令錯誤不汙染高階計畫
```

---

## 6. 深度標準（防止過度壓縮）

1. **推理鏈**：為什麼 A 導致 B？機制是什麼？不能只寫「A 導致 B」
2. **對比完整性**：原文有 A vs. B，整理後不得壓縮成「A 比 B 好」
3. **具體數字**：所有出現的百分比、倍數、規模數字都要保留
4. **例外與限制**：作者提到的邊界條件、失效場景都要保留
5. **圖表對應文字**：每張重要圖旁邊要有說明文字

**判斷基準**：整理後讓讀者理解「為什麼作者這樣設計」，不只是「作者做了什麼」。

## 7. 品質檢查清單

- [ ] Frontmatter 所有必填欄位已填寫
- [ ] 開頭有摘要段落（不超過 5 句）
- [ ] 每個主要概念的「為什麼」有保留，不只有結論
- [ ] 所有重要圖片有放置（在對應段落下方）
- [ ] 對比分析用表格或對比列表呈現，未壓縮成一句話
- [ ] 實驗數字完整（Baseline、本文方法、提升幅度）
- [ ] 結尾有「關鍵數據速查表」（如有數字型內容）

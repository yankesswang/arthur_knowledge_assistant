# 投資筆記整理規範

每次整理投資筆記（Substack 分析文、podcast、訪談、財報），必須遵循以下格式。

> **語言、圖片判斷、速查表格式**見 CLAUDE.md 全域規範，本文不重複。

---

## 1. 檔名規則（必遵守）

```
YYYY-MM-DD 自訂標題.md
```

- **日期**：使用整理日期（`date` frontmatter 的值），格式 `YYYY-MM-DD`
- **標題**：不需要照搬原文標題，自行提煉「核心標的 + 核心論點」
- 標題要讓人光看檔名就知道「這篇在說誰、說什麼」

**好的檔名範例**：
```
2026-04-21 ARM架構的長線投資邏輯與操作策略.md
2026-04-20 ENTG：台積電2nm超級循環下，耗材板塊的最佳卡位.md
```

**差的檔名範例**：
```
2026-04-21 MimiVsJames Substack筆記.md   ← 只有來源，沒有論點
2026-04-21 ARM筆記.md                     ← 太籠統
ARM架構分析.md                            ← 沒有日期
```

## 2. Frontmatter（必填欄位）

```yaml
---
title: 中文標題（與檔名標題一致）
date: YYYY-MM-DD（整理日期）
sector: 投資板塊（中文）
tags:
  - 核心主題1
  - 核心主題2
stocks:
  - TICKER1
  - TICKER2
url: 原始連結
---
```

## 2. TL;DR（必須放在標題後的第一個區塊）

用 `[!abstract]` callout，**一句話**包含以下四個元素：

```
核心轉型/結構性變化 + 關鍵機制（為什麼） + 具體數字 + 操作建議（時間點 + 動作）
```

**範例（ARM）**：
> ARM 正從「手機概念股」轉型為「AI基建功耗解決方案」，推論時代每瓦效能優勢從手機延伸至資料中心；AGI CPU 代表商業模式從「每顆抽 0.1–2 元」跨足「每顆收 1000 元以上」，年營收有望從 40 億成長至 150 億；但短期手機週期逆風使未來 1–2 季財報承壓，**操作建議等股價回落止跌後分批建長倉，看到 2027–2028 年 AGI CPU 放量的主升段**。

## 4. 正文結構

### 4a. 章節規範

- 用中文數字編號主要章節（一、二、三...），子節用 `1-1`、`1-2` 格式
- 每個章節開頭可先放**核心數據表格**，讓讀者在讀論述前先有數字錨點
- 每個章節必須有**投資含義**，不只是產業知識整理

**核心數據表格範例**（放在章節開頭，見 ARM 筆記）：

```markdown
| 時間 | ARM 在 AI 伺服器 host CPU 的市佔率 |
|------|----------------------------------|
| 2025 年 | 約 25% |
| 2026 年（ARM 預估） | 接近 50% |
| 2029 年（研究機構預估） | 90% |
```

### 4b. Callout 工具

| 工具 | 用途 |
|------|------|
| `[!quote]` | 作者的關鍵原話（原文引用） |
| `[!tip]` | 投資含義、選股邏輯 |
| `[!warning]` | 風險、反向指標、操作注意 |
| `[!info]` | 背景知識、市場結構、為什麼現在發生 |
| `[!note]` | 重要細節、補充說明、CEO 決策的觀察 |
| `[!danger]` | 極端風險、邏輯崩潰訊號 |
| Code block | 因果鏈、時間軸、商業模式計算、對比結構 |
| Table | 數據比較、多標的對照、情景分析 |

### 4c. Code Block 的具體用法

Code block 不只用來放計算，這兩篇最有效的用法是**結構化的因果流**：

```
訓練 vs. 推論的三大差異：

【一、運算規模】
訓練 → 一次性爆發，幾個月跑完就結束
推論 → 長期、連續、24/7 不間斷
差距：推論總量 > 訓練量的 10 倍以上
```

適合放 code block 的情境：
- 「舊世界 vs. 新世界」的對比結構
- 商業模式的計算（每顆抽 0.1 元 vs 每顆賣 1000 元）
- 時間軸演進（2026 Q4 → 2027 → 2028 的里程碑）
- 多個利多/利空的集中引爆邏輯
- 因果鏈（A 發生 → B 成立 → C 受益）

### 4d. 深度標準（防止過度壓縮）

- **每個投資觀點的「為什麼」必須完整**：因果推論、邏輯鏈、類比說明都要保留，不能只寫結論句
- **對比分析必須完整重現**：「舊模式 vs. 新模式」、「A 公司 vs. B 公司」不得壓縮成一句話
- **每一個論點的支撐論據都要納入**：具體例子、數字佐證、產業機制說明
- **風險分析要有層次**：說明傳導機制（為什麼這個風險會發生、如何影響股價）
- **篇幅基準**：整理後的內容密度應與原文相當，不應大幅短於原文

## 5. 投資框架（必寫，放在結尾前）

分三個時間維度，每個維度都要有**跟蹤指標 + 操作建議**，不只是描述性文字：

### 短期（事件驅動）

```
觸發因素（預期發生）：...
跟蹤指標：...
操作：財報前空手 / 財報後等止跌 / 分批建倉
```

### 中期（結構性，6–18 個月）

```
主要受益驅動：...
連帶影響（利空）：...
關鍵里程碑（時間軸）：
  2026 Q3：...
  2026 年底：...
  2027 年：...
```

### 長期（主題性）

```
核心主線：...
基礎假設（什麼條件下這個故事還在）：...
預期股價發動時間：...
操作方式（底倉 / 交易倉比例）：...
```

### 核心風險（必寫）

用 `[!warning]` callout，每個風險點**必須說明傳導機制**：
- 風險是什麼 → 為什麼會發生 → 如何影響股價 → 何時應停損或重新評估

## 6. 圖片處理（投資筆記專屬）

**保留**：K 線圖、季節性勝率表、產業鏈結構圖、財報數字截圖、任何有數字/標籤的圖表、產品對比圖、公司/廠區位置圖（有分析意義的）

**刪除**：文章封面橫幅、品牌 Logo、純裝飾圖

**本地附件**（`![[Pasted image xxx.png]]`）：直接保留，放在對應段落

**Substack CDN 圖片**（`https://substackcdn.com/...`）：
```markdown
![圖表說明文字](https://substackcdn.com/image/fetch/...)
> *圖：說明這張圖要讀者看懂什麼*
```

圖片放置位置：緊接在對應段落文字之後，不集中堆在文末。

## 9. 整理完成後必須更新投資操作建議總表

每次整理完投資筆記，**必須同步更新**：
`/home/trx50/Documents/arthurwang_DB/投資/投資操作建議總表.md`

每篇筆記在總表新增一個個股操作區塊，格式：

**標題**：`#### TICKER（公司名）— 一句話定位`

**1. 操作建議表格**（必填）：

| 欄位 | 內容 |
|------|------|
| 現價 / 推薦時股價 | |
| 進場區間或觀察點 | |
| 目標價（第一目標） | |
| 目標價（第二目標） | |
| 停損參考 | |
| 關鍵催化劑時間點 | |

**2.** `[!tip]` **操作邏輯**（必填）：2–3 句說明「為什麼現在買」、「什麼邏輯」

**3.** `[!warning]` **核心風險**（必填）：可能錯在哪裡、何時應停損或重新評估

**4. 來源 wikilink**（必填）：`📖 參考來源：[[筆記標題]]`

**更新注意**：
- 若總表已有該 ticker，更新數字和時間點，不重複新增區塊
- 更新日期需同步修改總表 frontmatter 的 `date` 欄位
- 板塊區對應：AI半導體 / 太空 / 能源 / 宏觀策略 / 科技軟體

## 10. 品質標準

1. **3 秒可判讀**：TL;DR 包含轉型邏輯 + 關鍵數字 + 操作時間點
2. **有觀點、有數字**：不只整理事實，要提煉投資邏輯
3. **有批判性**：明確說作者可能的偏差或錯誤假設，說明傳導機制
4. **可操作**：具體到哪個 ticker、什麼觸發條件、什麼時候進出
5. **有速查表**：所有關鍵數字集中在最後，不需要重讀全文
